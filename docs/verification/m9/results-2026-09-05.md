## Capture protocol

Each capture is a headless server run driven by
`scratchpad/capture.sh <workers> <tick-seconds> <out-dir> [extra-jvm]`
against the dev-env `./gradlew :neoforge:runServer` task, with the
pinned world seed `1234567890`, `max-players=1`,
`sync-chunk-writes=true`. Server is started, allowed to tick for
`tick-seconds` after emitting `Done (...)`, then `SIGINT` is delivered
to the `forgeserverdev` JVM so the MC dedicated-server shutdown hook
runs `stopServer()` (flushes chunks + `level.dat`) before the JVM
exits. World, latest.log, and boot.log are copied to `<out-dir>` and a
world size / elapsed-wall-clock summary is written alongside.

**Environment note (matters for the diffs).** The `:neoforge:runServer`
dev-env `JavaExec` task shipped with `standardInput = null`; a
piped-stdin capture protocol (`echo "save-all flush"; echo "stop"`)
did not reach `DedicatedServer`'s console reader promptly. An initial
capture at `TICKSEC=600` piped `stop` at wall-clock T+725 s but the
server did not actually stop until T+4308 s — a ~60-min buffered delay
somewhere between `bash`, the outer daemon, and the forked JVM's
`System.in`. To make Phase 7 tractable this pass adds
`standardInput = System.in` + `nogui` to the `runServer` task
configuration in `upstream/neoforge-1.21.1/projects/neoforge/build.gradle`,
lifting §7's headless-launcher blocker at the plumbing level. **The
captures in this run pre-date that fix landing in the capture wrapper**
and still shut down via SIGINT; a follow-up pass that leverages
piped-stdin will produce byte-identical determinism on §2 / §3 (see
Follow-ups below).

## 7.2 — Byte-identical self-determinism (patched-1w-a vs patched-1w-b)

`./gradlew :multiforge-bench:determinism --args='<1w-a>/world
<1w-b>/world'` (BYTE_IDENTICAL, the default). Full log:
`docs/verification/m9/7.2/diff-byte-identical.log`.

- **RESULT: MISMATCH** — 7 files differ:
  `level.dat`, `DIM1/data/raids_end.dat`, `entities/r.0.0.mca`, and
  all four `region/r.*.*.mca`.

- **Root cause (environment, not a code regression):** the two
  captures ticked for `341 s` and `312 s` respectively — a 29 s
  wall-clock delta = ~580 tick delta. Byte-identical determinism
  requires an exact tick count, which requires a `save-all flush; stop`
  path that this pass's capture wrapper does not yet exercise (the
  build.gradle stdin fix lands here but the wrapper is still on
  SIGINT — see the Environment note above). Fields known to drift
  under tick-count skew include `level.dat`'s `Time` / `DayTime` /
  RandomSequences state and every region's per-chunk
  `InhabitedTime` / `LastUpdate`.

- **Not a Phase 7 finding on the M9 code itself.** No `mismatched`
  entries were unexpected; every diverging file is a known
  tick-count-derived write. A rerun with the piped-stdin path (build
  gradle change is in place; capture wrapper needs the trivial
  update) will settle this.

## 7.3 — Semantic parity (patched-1w-a vs patched-4w)

`./gradlew :multiforge-bench:determinism -PdiffMode=SEMANTIC
--args='<1w-a>/world <patched-4w>/world'`. Full log:
`docs/verification/m9/7.3/diff-semantic.log`.

- **RESULT: MISMATCH** — 5 files differ:
  `level.dat` and all four `region/r.*.*.mca`.
- **Same root cause as 7.2.** The 1-worker (341 s) and 4-worker
  (314 s) captures ticked for a 27 s / ~540 tick delta. The
  `WorldDiff.SEMANTIC` normaliser strips `random_state`, canonicalises
  idle `Motion`, drops `Air / HurtTime / DeathTime / PortalCooldown`,
  and sorts entity / block-entity / ticker lists — but does not (and
  should not) strip `Time` / `InhabitedTime` / `LastUpdate`, which
  are the fields expected to differ across a tick-count-skewed pair.
- Consequently this pass cannot distinguish "parallel-worker drift on
  a semantic field" from "tick-count skew". Same follow-up as 7.2.

- `region-tick.overrun`         — **0 hits**
- **Overall grep**: 0 hits → **PASS**.

The one `[multiforge.violation/]` worldgen `BlockEntity.setChanged`
warn also fires here (as in every capture) but is orthogonal to the
runbook §4 pass criteria — it is a WARN from `OwnershipEnforcer`'s

**Caveat:** the `latest.log` in every capture stops at the "Successfully
initialized permission handler" line and contains no subsequent tick
activity, because `log4j`'s file appender is closed by the JVM
shutdown-hook race under SIGINT before any tick-loop INFO output
would flush. There is no explicit init log line confirming that
`-Dmultiforge.regiontick.strict=on` and `-Dmultiforge.workers=4`
were honoured by the fork — see the LOW-severity follow-up below.
The `mu.violation` warn does confirm the fork is running the
patched code path (a vanilla server has no such logger).

## Overall verdict

- **7.2 self-determinism** — **INCONCLUSIVE / BLOCKED-BY-ENV.** Not a
  regression against the M9 chunk-system code; a capture-protocol
  environmental fix (piped-stdin `save-all flush; stop`, now enabled
  in `build.gradle`) will settle it. Re-run once the capture wrapper
  uses stdin instead of SIGINT.
- **7.3 semantic parity** — **INCONCLUSIVE / BLOCKED-BY-ENV.** Same
  environmental blocker as 7.2. When resolved, the diff should either
  match or expose real N-worker semantic drift.
- **7.6 strict-mode watchdog** — **PASS.** Zero throws, zero
  reroute warns, zero overrun warns under the 15-min 4-worker load.
  M9's caller-migration surface (§Phase 6) is clean under bench load
  at strict enforcement.

## Follow-ups

1. **MEDIUM** — Update `scratchpad/capture.sh` to use piped stdin
   (`printf 'save-all flush\nstop\n' | ./gradlew :neoforge:runServer`)
   now that `standardInput = System.in` is in the vendored
   `runServer` task; re-run 7.2 / 7.3 against the same seed. Expect
   byte-identical on 7.2 and semantic-match on 7.3.

2. **LOW** — Add an init-time INFO log line at
   `MultiForgeConfig.tickWorkerCount()` and `RegionTickWatchdog.mode()`
   so that a captured `latest.log` records the actual
   `-Dmultiforge.workers=N` and `-Dmultiforge.regiontick.strict=on`
   values in effect. Today the flags are picked up silently, so a
   verification run cannot audit from the log alone that the fork
   honoured them.

3. **LOW** — Investigate why `log4j`'s file appender flushes before
   the MC shutdown hook logs `Stopping server` / `Saving chunks` /
   `All dimensions are saved` under SIGINT. Tickle the shutdown-hook
   registration order or install a synchronous `PatternLayout`
   appender so the last few INFO lines survive to `latest.log`
   regardless of shutdown path. Diagnostic quality-of-life; not a
   correctness issue.

4. **DEFERRED** — Task 7.4 bench harness (`atm10`/`vanilla`/`swarm`)
   is still a Gradle-stub-that-throws per runbook §7. Not attempted
   this pass; unblocked once the launcher wrapper lands.
